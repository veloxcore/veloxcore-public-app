FAQ

Common questions.

Questions we get before every ML engagement.

Why do most ML models never reach production?
Three consistent reasons: feature pipelines that don't match training data in production (training-serving skew), no evaluation harness to catch model drift, and no automated retraining when the data distribution shifts. These are infrastructure problems, not model problems — and they're solvable before a model ever trains.
Do we need Azure ML, or can we use our existing infrastructure?
We can work with your existing infrastructure — Databricks, SageMaker, on-prem Kubernetes — but we'll be honest if Azure ML is a better fit for the use case. We're not wedded to the Microsoft stack for ML; we're wedded to what works in production.
What's the difference between a RAG system and fine-tuning?
RAG (retrieval-augmented generation) grounds the model in your documents at query time — fast to build, easy to update, no model training required. Fine-tuning trains the model on your data to change its behaviour. For most enterprise use cases, RAG is the right starting point. We'll advise which fits your problem before any work begins.
How do you control Azure OpenAI costs in production?
Token budget alerts, prompt caching, model routing (use GPT-3.5 for simple queries, GPT-4o for complex ones), output length limits, and provisioned throughput units for predictable workloads. We also add cost dashboards per use case so you can see exactly where the spend is going.
