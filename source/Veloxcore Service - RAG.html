What you get

Production RAG.
Not a search wrapper.

A production RAG system is not a call to embeddings + a call to GPT. It's a chunking strategy, a retrieval pipeline, a re-ranking layer, an evaluation harness, and a citation system.

Production RAG pipelineDocument ingestion, chunking strategy (semantic or fixed, with overlap), embedding generation, and Azure AI Search index — set up for your document types and query patterns.
Hybrid retrievalVector similarity + BM25 keyword search + semantic ranker — so keyword-exact queries and semantic queries both return the best chunks, not just the most similar ones.
Citation systemEvery LLM response includes chunk-level citations — document name, page, and the exact passage retrieved. Users can verify every answer against the source.
Groundedness evaluationAn automated evaluation harness that checks every response against retrieved chunks — flagging answers that are not supported by the retrieved context before they reach users.
Document update pipelineWhen source documents change, the index updates automatically — via Azure Blob Storage triggers or scheduled re-indexing. No manual re-ingestion required.

FAQ

Common questions.

Questions we get on almost every RAG discovery call.

How do you choose chunk size and overlap?
Chunk size is a function of your document structure and query patterns. For narrative documents (contracts, policies), we typically use 512–1024 token chunks with 15–20% overlap. For structured documents (tables, product specs), we often use smaller chunks or preserve table structure as atomic units. We always run retrieval quality experiments on 50+ representative queries before committing to a strategy.
What if our documents change frequently?
We set up event-driven re-indexing via Azure Blob Storage triggers — when a document is updated, the affected chunks are automatically re-ingested and the stale vectors replaced. For high-velocity document sets, we can configure near-real-time indexing. The LLM layer always queries the current index state.
How do you handle access control — different users seeing different documents?
Azure AI Search supports security filters that enforce document-level access control at query time. We tag each chunk with the access groups that can see it, and every retrieval query includes a filter that limits results to chunks the requesting user is authorised to access. This is enforced server-side — it's not possible to retrieve unauthorised chunks by manipulating the query.
What document formats can you ingest?
PDF, Word, PowerPoint, Excel, HTML, plain text, and markdown natively. For scanned PDFs and images, we use Azure Document Intelligence (Form Recognizer) for OCR. For structured data in databases, we build custom extraction pipelines that convert rows into text chunks. We've ingested everything from 40,000-page legal corpora to real-time database tables.
