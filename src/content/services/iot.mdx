faqs:
  - q: "What device hardware do you support?"
    a: "Any device that can run the Azure IoT Device SDK — which covers C, Python, Node.js, Java, and .NET. For constrained devices without an OS, we use the embedded C SDK. IoT Edge requires a Linux-capable device (x64, ARM64, or ARM32). We'll assess your hardware in the audit phase and flag any constraints before any work begins."
  - q: "How does zero-touch provisioning actually work?"
    a: "DPS uses X.509 certificate chains. We generate a root CA, create an intermediate CA per device batch, and provision individual device certificates at manufacturing time. When a device powers on for the first time, it presents its certificate to DPS, which validates it against the registered root CA, assigns the device to the correct IoT Hub, and applies the group twin configuration — all in under 5 seconds with no human intervention."
  - q: "Can ML inference run on the device, not in the cloud?"
    a: "Yes. We export trained models to ONNX format and deploy them via IoT Edge modules to capable devices. Inference runs locally — sub-millisecond, no cloud round-trip, and continues working during connectivity loss. The cloud receives the inference output, not raw sensor data, which also dramatically reduces message volume and cost."
  - q: "How do you handle firmware updates across 10,000+ devices?"
    a: "OTA firmware updates via IoT Edge deployment manifests — deployed to device groups in waves (1%, 10%, 100%) with automatic rollback if error rates spike above a threshold. We also set up the Device Update for IoT Hub service for devices that need delta updates to minimise bandwidth on constrained connections."
