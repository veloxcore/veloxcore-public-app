These are infrastructure problems, not model problems — and they're solvable before a model ever trains."
  - q: "Do we need Azure ML, or can we use our existing infrastructure?"
    a: "We can work with your existing infrastructure — Databricks, SageMaker, on-prem Kubernetes — but we'll be honest if Azure ML is a better fit for the use case. We're not wedded to the Microsoft stack for ML; we're wedded to what works in production."
  - q: "What's the difference between a RAG system and fine-tuning?"
    a: "RAG (retrieval-augmented generation) grounds the model in your documents at query time — fast to build, easy to update, no model training required. Fine-tuning trains the model on your data to change its behaviour. For most enterprise use cases, RAG is the right starting point. We'll advise which fits your problem before any work begins."
  - q: "How do you control Azure OpenAI costs in production?"
    a: "Token budget alerts, prompt caching, model routing (use GPT-3.5 for simple queries, GPT-4o for complex ones), output length limits, and provisioned throughput units for predictable workloads. We also add cost dashboards per use case so you can see exactly where the spend is going."
