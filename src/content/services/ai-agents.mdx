faqs:
  - q: "When does a workflow warrant an agent vs. a simpler LLM call?"
    a: "Use an agent when the task requires multiple sequential decisions, where the output of one step determines what to do next, and where the steps involve calling external tools. If your task is a single-turn question-answering problem, a standard RAG pipeline is simpler and more reliable. We help you make this distinction at the start of every engagement."
  - q: "What happens when an agent makes a mistake?"
    a: "Every production agent we build has configurable human-in-the-loop checkpoints for high-risk actions, retry logic with exponential backoff for transient failures, and a full audit trail for post-hoc debugging. For irreversible actions (sending emails, writing to databases, making payments), we always require explicit human approval in the first production phase."
  - q: "How do you handle agents that need to wait for hours or days?"
    a: "For durable workflows — where an agent submits a request and needs to wait for a human response or an external event — we use Azure Durable Functions or Logic Apps rather than keeping a thread alive. This gives you guaranteed delivery, resumability, and cost efficiency even for workflows that span days."
  - q: "Can agents integrate with our existing systems?"
    a: "Yes — the tool layer is where we integrate with your existing stack. We've built tool integrations for CRMs, ERPs, databases, REST APIs, email/calendar, SharePoint, and custom internal systems. If it has an API or a database connection, we can build a tool for it."
