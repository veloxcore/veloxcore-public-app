## The problem

The UN Department for General Assembly and Conference Management (DGACM) produces tens of thousands of official documents every year across six constitutional languages: English, French, Arabic, Spanish, Russian, and Chinese. The Official Document System (ODS) held this corpus — invaluable and effectively unsearchable under time pressure.

Traditional keyword search failed in two ways. A query in English would not surface Arabic or Chinese equivalents without knowing the precise terminology in each language. And voting records — how each member state voted on each resolution — lived in a separate SQL Server database with no unified interface. Answering a simple question like "How did the P5 vote on Resolution 2334?" meant switching systems and synthesising results manually.

## The solution

We built a conversational AI assistant behind a customised LibreChat frontend. Two specialised agents were deployed:

**DGACM Mini** handles queries over the ODS document corpus and voting database. It is the primary interface for staff and delegates — natural language questions in any of the six official languages, answered with grounded citations.

**Athena Help Assistant** is scoped to DGACM's internal Athena documentation system, handling support queries without touching the main document corpus.

Each UN official language has its own dedicated Azure AI Search index. A question in Arabic is embedded, searched, and answered from the Arabic corpus — no translation, native-language retrieval throughout. Semantic hybrid search (dense HNSW vectors plus sparse keyword matching, scored by Azure's semantic reranker) ensures precision at scale.

## Architecture

The backend is a FastAPI application orchestrated by LangGraph's ReAct pattern. An `AgentFactory` maps request types to concrete agent classes. Each agent reasons about which retrieval tools to invoke, executes them iteratively, and synthesises a grounded response — rather than following a fixed pipeline.

The `VotingDataAgent` translates natural language into parameterised SQL, queries the SQL Server database, and returns structured results that the main agent weaves into its response alongside document context. Two middleware layers handle authentication and PII detection before any query reaches the language model.

Answer quality is measured continuously through Azure AI Foundry across four dimensions: relevance, coherence, groundedness, and intent resolution. Both positive and negative evaluation datasets are maintained so regressions surface before users encounter them.

## Outcome

Staff and delegates can now ask a single natural language question — in any of the six official languages — and receive a unified answer that draws on document content and voting records together. What previously required consulting two separate systems, two sets of credentials, and manual synthesis now resolves in one conversation turn. The Athena Help Assistant has absorbed a class of internal support queries that previously required human intervention. The modular architecture means new document collections or specialised agents can be added without rearchitecting the system.
